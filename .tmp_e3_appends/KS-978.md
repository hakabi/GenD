### Detailed requirements (v1.4)

#### A. Preconditions and dependencies

* OAuth / connectivity per Epic E1 (**[KS-989](https://gendvn.atlassian.net/browse/KS-989)**, **[KS-990](https://gendvn.atlassian.net/browse/KS-990)**, **[KS-976](https://gendvn.atlassian.net/browse/KS-976)**) as applicable.
* Obtain a fund identifier from a prior **`get_funds`** call ( **`Name`** and/or **`ID`** from **`get_fund_description`** )—**no** UI-exported IDs.

#### B. Consistency and null handling (5.2)

* **Prompt (example):** *Fetch the full details of fund `<FUND_ID>`, including its description.* (Natural language; agent must invoke MCP tools.)
* **Pairing:** Compare **`get_fund_description`** row to **`get_funds`** row for the **same** fund using **`Name`** match or **`ID`** if present in both payloads.
* **Non-contradiction:** `FundManagerName`, pipeline / asset class fields, and dates must not conflict between tools; document formatting tolerance (trim, casing).
* **Nulls:** Missing `Description` or optional fields must appear as **null** or explicit empty—**no** fabricated placeholder text.
* **Timezone:** If datetime fields exist, capture how offsets appear **in the JSON** only.

#### C. Ratings (explicit exclusion)

* **Do not** execute `get_rating_summary` / `get_rating_details` in v1.4; matrix / evidence marks **S** with rationale *not in 8-tool inventory*.

#### D. Matrix

* Guide **section 6** row **5.2 Fund fetch** — coordinate totals with **[KS-993](https://gendvn.atlassian.net/browse/KS-993)**.

### Acceptance criteria (BDD, v1.4)

_Scenario 1 — Happy path_

* **Given** a fund returned by **`get_funds`** and describable via **`get_fund_description`**
* **When** the tester runs the section **5.2** flow
* **Then** description and overlapping attributes are **non-contradictory** between tools for the same fund keys documented in evidence

_Scenario 2 — Error path_

* **Given** a non-existent or inaccessible fund identifier
* **When** details are requested
* **Then** the MCP response is a **controlled error** or **empty authorized result**—no other-tenant payloads

_Scenario 3 — Edge case_

* **Given** `Description` is **null**
* **When** the tester fetches details
* **Then** the response shows absence explicitly and the agent does **not** invent rating or narrative filler
