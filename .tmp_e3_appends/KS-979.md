### User Story (v1.4)

> As an **Internal QA Tester**, I want **repeatable `get_documents` metadata for an authorized fund** so that **guide section 5.3 passes** on the **8-tool** surface without document-portal UI or invented filenames.

### Overview (v1.4)

Executes **guide section 5.3 — Document retrieval test** using **`get_documents` only** for document listing. Enumeration / runtime filter rules: **[KS-991](https://gendvn.atlassian.net/browse/KS-991)**. **Out of scope:** ratings, Aloha search, `read_data`, `list_table`, `describe_table`.

**`<FUND_ID>` in prompts:** In MCP, fund scoping commonly uses **fund name string** with `filterType: fund` + `filterValue` (see **[KS-992](https://gendvn.atlassian.net/browse/KS-992)** cross-tool notes). Document the actual filter tuple used in evidence.

**Runtime rule:** At least **one** filter dimension is required (fund/company + value, categories, and/or date window)—zero-filter calls must return a **clear validation error**, not a silent success (**KS-991** schema vs runtime gap).

### Detailed requirements (v1.4)

#### A. Preconditions and dependencies

* Valid OAuth session; **`get_documents`** registered per **[KS-991](https://gendvn.atlassian.net/browse/KS-991)**.
* Pick a fund identifier from **`get_funds`** / **`get_fund_description`** that is expected to have documents **or** document the **soft-empty** (`success: true`, `data: []`) outcome explicitly.

#### B. Document list and stability (5.3)

* **Prompt (example):** *List all documents associated with fund `<FUND_ID>`.*
* **Parameters:** Use `filterType` / `filterValue` and/or `documentCategories` and/or `startDate`/`endDate`; set `excludeContent: true` unless content inspection is required—watch **2MB** cap in tool description.
* **Repeat call:** Same parameters **twice** in-session; compare stable keys (`ID`, `Title`, `Documentdate`, `Documentcategories`) and document sort order if ordering is not guaranteed.

#### C. Security and empty states

* **No** filenames or companies invented by the agent when the tool returns empty `data`.
* **Tenant scope:** Errors or empty authorized lists only—**no** cross-fund rows.

#### D. Matrix

* Guide **section 6** row **5.3 Documents** — align with **[KS-993](https://gendvn.atlassian.net/browse/KS-993)**.

### UI/UX & front-end considerations (v1.4)

* Capture whether the agent surfaced **raw tool JSON** or paraphrased; prefer attaching JSON to Jira/QA repo per guide section 8.

### Acceptance criteria (BDD, v1.4)

_Scenario 1 — Happy path_

* **Given** a fund with at least one document visible via **`get_documents`**
* **When** the tester runs two identical listing calls
* **Then** stable identifiers and metadata fields match between calls (modulo documented ordering)

_Scenario 2 — Error path_

* **Given** invalid filter combination or inaccessible fund
* **When** documents are requested
* **Then** validation error or empty authorized result—**no** silent cross-tenant data

_Scenario 3 — Edge case_

* **Given** **zero** documents for the fund
* **When** listed
* **Then** `recordCount` / empty `data` is explicit and the agent adds **no** placeholder files
