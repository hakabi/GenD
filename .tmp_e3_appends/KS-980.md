### User Story (v1.4)

> As an **Internal QA Tester**, I want **`get_activity` timeline, `get_notes` bodies (where authorized), and a grounded `analyze_notes` summary** so that **guide section 5.4 passes** on the **8-tool** surface without Dynamo UI.

### Overview (v1.4)

Delivers **guide section 5.4 — Activity & notes test** using **`get_activity`**, **`get_notes`**, and **`analyze_notes`**. Enumeration + runtime filter behavior: **[KS-991](https://gendvn.atlassian.net/browse/KS-991)**. Cross-tool fund/company filter patterns: **[KS-992](https://gendvn.atlassian.net/browse/KS-992)**. **Out of scope:** `read_data`, `search_aloha_funds`, ratings, schema tools.

**Known limitations (QA):** `get_activity` and `get_documents` publish optional JSON parameters but enforce **≥1** runtime filter (**KS-991**). `get_notes` defaults to **Investment Due Diligence** categories unless overridden; `analyze_notes` may return **zero** rows for funds whose notes are outside that default—document as limitation or use broadened categories where the tool allows.

### Detailed requirements (v1.4)

#### A. Preconditions and dependencies

* Valid OAuth session; all three tools registered per **[KS-991](https://gendvn.atlassian.net/browse/KS-991)**.
* Select a fund with **both** activity and notes where possible; otherwise execute the **empty branch** scenarios explicitly.

#### B. Activity chronology (5.4)

* **Filters:** Use `fundNames` and/or `companyNames` / date windows per schema; avoid zero-filter calls that only pass `limit`.
* **Ordering:** Verify `Date` ordering is chronological **or** document server ordering rule from payload.

#### C. Notes and analysis grounding (5.4)

* **`get_notes`:** Prefer `includeBody: false` for listing passes unless thematic analysis requires text; respect `maxBodyLength` when including bodies.
* **`analyze_notes`:** Summary/highlights must be **traceable** to returned note text—**no** generic market boilerplate. Note **full note bodies may appear in MCP responses**—redact in shared artifacts (**KS-992** egress notes). Processing path (internal vs external LLM) may be **vendor TBD**—record evidence either way.

#### D. Matrix

* Guide **section 6** row **5.4 Activity/Notes** — align with **[KS-993](https://gendvn.atlassian.net/browse/KS-993)**; **Large dataset** column per original UI/UX notes.

### UI/UX & front-end considerations (v1.4)

* For long threads, attach full JSON outside chat; link path in Jira.

### Acceptance criteria (BDD, v1.4)

_Scenario 1 — Happy path_

* **Given** a fund with activity and notes visible via MCP
* **When** the tester runs the section **5.4** chain
* **Then** activity ordering is plausible, `get_notes` payloads align with `analyze_notes` themes, and analysis does not invent facts absent from notes

_Scenario 2 — Error path_

* **Given** invalid fund identifier or no access
* **When** the chain runs
* **Then** tools return errors or empty authorized results without leaking other users' content

_Scenario 3 — Edge case_

* **Given** **no notes** (or **no** activity) for the fund
* **When** executed
* **Then** empties are explicit and `analyze_notes` states insufficient data—**no** fabricated note text
