What changes

Reset on retry — when a retry starts, the request's steps/cases move to Queued/Running for the new attempt; stale FAILED from the prior run is cleared.
Attempt label — a "Re-running · attempt N" marker so it's clear this is a fresh run, not the old result.
Old attempt in History — the previous (failed) attempt stays available under History rather than lingering in the live Execution tree.
One source of truth — the header status and step statuses are always consistent (header RUNNING ⇒ no step still reads FAILED from a past run).
