Navigation — request list to request detail. How the case-first designs connect to the existing list. Four frames: the widened list, what happens on click, the detail page in two alternative layouts, and its supporting tabs. Recommendation is a full page with its own URL — not a popup or an overlay. The left panel is unchanged from the live system — Requests, Test cases (Failed / All cases / Executed history), Test groups, Knowledge, Dashboards. Nothing in this proposal requires a navigation change. Prepared by the Business Analyst, 19 August 2026.

From the list to the cases

The list stays. Clicking a row navigates to a real page, so the detail can be linked, shared, bookmarked and reached with the back button. The case-first designs (D1, D2 or D3) live on that page, under a Cases tab that opens by default.

/requests — the list
/requests/REQ-1042 — detail, Cases tab (default)
/requests/REQ-1042?tab=info — the prompt and attributes
/requests/REQ-1042?tab=execution — the run log
/requests/REQ-1042?tab=history — lifecycle events
Frame 1

The list, with the preview pane removed

Dropping the right-hand preview gives the list the full width. The prompt still truncates exactly as it does today — that is unchanged, and the full text is on the detail page. What the extra width buys is the columns that were never there: outcome, cases, and who is blocked.

What happens on click The browser navigates — /requests → /requests/REQ-1042. The URL changes, so the page can be bookmarked, pasted into Jira or Slack, and reopened later. Browser back returns to the list with scroll position, filters and selection preserved. Esc does the same.

The detail opens on the Cases tab. Info, Execution and History move here from the old right-hand pane — on this page the cases are the subject and those three are supporting evidence.

Interaction specification

ActionBehaviourWhy
Click anywhere on a rowNavigate to /requests/REQ-1042Whole row is the target; the key is only the visual affordance
Click the checkboxSelect, do not navigateBulk actions need a way to select without leaving
↑ ↓ then EnterMove through rows, open the focused oneQA working a backlog will use this constantly
Esc or browser backReturn to the list, restoring scroll, filters and selectionThe most common complaint about detail pages is losing your place
Middle-click / ⌘-clickOpen in a new tabFree once it is a real URL. Impossible with a modal
Paste the URL in JiraOpens the request detail on the Cases tabThe single strongest reason not to use a modal
Switch tabUpdates ?tab= so the tab is part of the linkLets someone link straight to the execution log of a failure
Accept / merge / extend a caseUpdates in place; counts in the header and the nav badge updateSame case may be visible in Test Cases › Proposed — both must agree

Two entry points, two questions

The same cases will be reachable from two places. That is fine, provided each answers a different question and a decision in one is instantly reflected in the other.

Entry pointQuestion it answersScope
Requests › REQ-1042 › CasesWhat did this request produce, and is the batch sound?One request, all 15 cases together, batch context and shared labels
Test cases › Proposed not built yetWhat needs my decision today, across everything?All unreviewed cases from every request, mixed together. Would slot in beside Failed / All cases / Executed history if adopted — it is not in the current navigation and this proposal does not require it

Why not a popup or an overlay

Modal / popupOverlay drawerFull page ✓
LinkableNoNoYes
Back button worksInconsistentInconsistentYes
Room for D2's five columnsOnly if near full-screenNoYes
Room for D3's expanded stepsCrampedNoYes
Survives an interruptionFeels like losing workPartlyYes
Right for the taskOne short decisionA quick glanceA 5–10 minute working session
If you want to keep a preview as well A middle option exists: keep the list full-width, and let hover or a spacebar peek show a small summary card — counts and the first few case names — without navigating. It gives the quick glance back without stealing the width. I would add it only if QA ask for it after using the full-page version, rather than building both up front.
