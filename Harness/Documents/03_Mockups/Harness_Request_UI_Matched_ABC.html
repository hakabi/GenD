Request page — matched to A, B and C

All three assume case review lives in a Proposed tab under Test Cases, and all three replace the single word failed with outcomes that say what happened. What differs is the shape each inherits from its counterpart.

The rule all three share, and the reason it matters Every design replaces the single word failed with outcomes that name what happened, and derives that outcome from what was produced rather than from an internal state field.

On the live system today, request #3ae938b9-e89 displays AWAITING_REVIEW after 3h 38m, while its generation phase actually failed and no cases exist. In all three designs above the same request reads Stuck / 0 cases / contributed nothing — because the outcome is computed from the absence of output, not asserted by a status field that was never updated.
