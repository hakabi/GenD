The root cause, in one picture. Every drifted value is two dimensions welded into a single token — the feature area fused with the fund it was tested against. Split them and the duplicates collapse.

Look at the first two: the same feature area, counted as two different values because they were tested against different funds. That is how Risk ended up with seven, why --grep @risk returns nothing, and why 287 cases produced 237 grouping values. The feature field answers what is being tested; a fund: label answers where. One field cannot hold both — so fund moves into namespaced labels[].
03What the walkthrough changed Four findings that move the build estimate — three of them downward.
① Feature is load-bearing twice over
It is simultaneously a directory on disk and a grep-able Playwright tag. So drift doesn't just muddle labels — it fragments the test repo's tree and the grep handles. Governing it is now the highest-value single change.
② Tag-based suites already work
The generated spec carries @aloha @public-fund-risk @qops, so --grep batch runs are live today. GROUPS shrinks to a UI over an existing engine.
③ Half the model already exists
Category is auto-assigned and filterable; a Labels field exists. MODEL and CLASSIFY shrink — an LLM already fills these fields. It needs a closed list, not a new pipeline.
④ The vocabulary has already collapsed — measured
287 cases · ~237 distinct values · ~202 of them used once. That is ≈1.2 cases per grouping value — an ID, not a taxonomy. Risk alone has seven values (risk-dashboard, public-fund-risk, total-endowment-risk-tab, …). This is the failure VOCAB prevents, already well advanced.
⑤ Phase A taxonomy already exists — blocking
fix(catalog): prefer managed app_project for Phase A taxonomy shipped 4 Aug. There is an existing taxonomy workstream. Do not present this vocabulary to the PO as a new idea until we know what Phase A covers.
04Where this goes — the automation ladder The workflow is the same at every rung; what changes is how much of Phase 1 a human still writes.
LEVEL 0
One prompt, one case
Single-test-case mode. Retrieval is scrolling; duplicates are found by memory.
YOU ARE HERE
LEVEL 1
One prompt, one family
Test Feature expands a request into positive / negative / boundary / security. Volume climbs fast — and retrieval starts to hurt.
LEVEL 2
Labelled & self-filing
Classified at ingest against a closed vocabulary. Suites are queries, so new cases join their group with no filing.
LEVEL 3
Coverage-driven generation
The heatmap drives the prompt: Harness proposes requests that fill empty area × type cells. QA reviews proposals instead of facing a blank page.
