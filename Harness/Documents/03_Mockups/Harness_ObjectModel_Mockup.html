Object model — make Request → Cases → Runs visible

Harness has a three-level model, but the UI never shows it — so users can't tell which request a case or run came from (the recurring "which one is this?" confusion). The fix is a consistent breadcrumb + "belongs to" chip on every case and run. Styled with the real tokens.css (dark).

Where the pattern applies (one consistent rule)

Executed history rows — show the parent REQ-#### + plain case name, not just a run slug.
Case detail — breadcrumb REQ-#### › Case; "belongs to" chip linking to the request.
Run detail / Run review — full breadcrumb REQ-#### › Case › Run as above.
Requests → Execution tab — already the top of the chain; label its children as "Cases" and "Runs" consistently.
Uses the friendly REQ-#### reference from QG-141 so the whole hierarchy reads in human terms, not UUIDs.
